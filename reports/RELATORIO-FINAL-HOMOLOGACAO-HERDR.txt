4. SOLUCAO DEFINITIVA PARA O WINDOWS
O template nativo do Herdr continua bloqueado no Windows:
  hc run --bg --name native-test --cwd C:\Work\dev\herdr.dev gfm-architect "Responda apenas NATIVE_OK."
Resultado:
  {"error":{"hint":"check the program name and cwd","kind":"spawn_failed",
  "message":"cannot start \"sh\": sh: not found on PATH"}}
O core reconstroi o PATH a partir do registro do Windows; prefixar o PATH do
processo nao resolve. A correcao nativa exigiria `sh` no PATH do core
(alteracao global nao autorizada).

Mecanismo oficial adotado no Windows: `.herdr/scripts/run-agent.ps1`.
- Le `.herdr/templates/gfm-<papel>.md`.
- Valida frontmatter e o comando `opencode --agent <papel>`.
- Para papeis primarios, executa `opencode run --agent <papel>` com o corpo do
  template e a tarefa.
- Para subagentes, delega via `orchestrator` e ferramenta `task`, repassando o
  corpo do template e a tarefa ao subagente.
- Suporta `-DryRun`.
- Nao cria shim/executavel falso de `sh`.

Comando de execucao:
  hc run --bg --name <papel> --cwd C:\Work\dev\herdr.dev powershell -NoProfile -ExecutionPolicy Bypass -File .herdr/scripts/run-agent.ps1 -Role <papel> -Task "<tarefa>"

5. CORRECAO DA SELECAO DE AGENTES
No OpenCode 1.19.0, `opencode run --agent <subagente>` emite:
  agent "<papel>" is a subagent, not a primary agent. Falling back to default agent.
Os papeis `tester`, `reviewer`, `security-reviewer` e `docs-writer` sao
subagentes e nao podem ser selecionados diretamente pela CLI.

Correcao aplicada: o wrapper chama `opencode run --agent orchestrator` com uma
instrucao explicita para usar a ferramenta `task` uma unica vez com
`subagent_type=<papel>` e repassar o prompt do template ao subagente. O log do
OpenCode registra `agent=<papel> mode=subagent`, confirmando que o papel correto
foi carregado.
