1. OBJETIVO
Resolver a falha `spawn_failed: cannot start "sh"` ao executar templates `gfm-*`
no Herdr Core 0.1.19 no Windows, sem alteracoes globais no sistema e sem criar
executavel falso de `sh`.

2. AMBIENTE VERIFICADO
- Windows 11 Pro 10.0.26300 (AMD64)
- Herdr Core hc 0.1.19; Herdr App 0.1.14
- OpenCode 1.19.0
- PowerShell 5.1 e PowerShell 7.6.9
- Git 2.55.0.windows.5
- `sh.exe` existe em `C:\Program Files\Git\bin\sh.exe`
- `sh` NAO esta no PATH do core do Herdr
- `%APPDATA%\herdr-core\config.toml` nao existe no ambiente original
- 8 templates `gfm-*` instalados em `%APPDATA%\herdr-core\templates`

3. DIAGNOSTICO
3.1 Template nativo falha
Comando:
  hc run --bg --name smoke --cwd C:\Work\dev\herdr.dev gfm-test "Responda apenas OK."
Resultado:
  {"error":{"hint":"check the program name and cwd","kind":"spawn_failed",
  "message":"cannot start \"sh\": sh: not found on PATH"}}
Log do holder:
  holder: t1: cannot start "sh": sh: not found on PATH

3.2 Config `shell` nao resolve templates
Em sessao isolada, `shell = ["cmd", "/d", "/s", "/c"]` em config.toml:
  - terminal interativo iniciou com o shell configurado;
  - template continuou falhando com `cannot start "sh"`.
Teste anterior com `shell = ["C:\\Program Files\\Git\\bin\\sh.exe"]` tambem nao
alterou o caminho de template. Conclusao: `shell` afeta terminais interativos e
recovery, mas o caminho de template usa `sh` literal no Windows.

3.3 PATH do core e reconstruido
Foi iniciado um core isolado com `C:\Program Files\Git\bin` prefixado no PATH do
processo. O terminal criado pelo holder mostrou o PATH do registro do Windows,
sem `C:\Program Files\Git\bin`. Uma variavel customizada (`GFM_TEST=abc123`) foi
herdada, mas o PATH foi substituido. Prefixar o PATH do processo que inicia o
core nao e suficiente.

3.4 Correcao nativa
A correcao nativa exigiria `sh` no PATH visivel pelo core (por exemplo, adicionar
`C:\Program Files\Git\bin` ao PATH do usuario e reiniciar o core). Isso e uma
alteracao global e NAO foi aplicada; depende de autorizacao explicita.

4. SOLUCAO IMPLEMENTADA (SEM ALTERACAO GLOBAL)
Criado `.herdr/scripts/run-agent.ps1`:
- le `.herdr/templates/gfm-<papel>.md`;
- valida frontmatter e o comando `opencode --agent <papel>`;
- monta o corpo do template + tarefa;
- executa `opencode run --agent <papel> "<corpo + tarefa>"`;
- suporta `-DryRun`;
- avisa quando o papel e subagente no OpenCode 1.19.0.

Execucao no Windows:
  hc run --bg --name <papel> --cwd <repo> powershell -NoProfile -ExecutionPolicy Bypass -File .herdr/scripts/run-agent.ps1 -Role <papel> -Task "<tarefa>"

Nao foi criado shim, link ou executavel falso de `sh`. Nenhuma variavel global
foi alterada. Nenhum `hc server stop/restart` foi executado no core padrao.
